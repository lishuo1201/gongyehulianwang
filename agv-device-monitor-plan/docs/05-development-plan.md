# 05 开发与学习计划：工业软件 Java 后端

适用对象：已有 7 年 Java 互联网开发经验、工业领域基础不足，希望应聘工业软件 Java 后端岗位的开发者。目标是能理解工业系统协作、实现并解释设备采集监控、应对有场景的面试追问。

本计划以阶段组织学习，每天 2～4 小时仅作参考。第 2 节保留的 5 天 MVP、10 天完善是工程预算，前 5 天约 17.5 小时的估算不包含完整学习验收；依赖、网络、并发测试和学习补正都可能延长工期。进度以实际验收为准，不为赶天数跳过理解或测试。

分工：你负责设计、推理和回答问题；Codex 负责编码、运行测试及解释结果。设计可用自然语言、伪代码或流程图表达，允许查阅项目文档，不要求你编写可执行代码。每轮围绕一个任务，同时检查工程结果和学习理解，两者分别记录。

## 1. 学习主线与深度

先阅读 [工业系统全景](02-architecture.md)，理解设备、PLC、协议接入、MES/WMS、执行调度和 Web 的职责，再把 Java 经验迁移到具体工业问题。完整链路的认识范围大于 Demo 的实现范围；保持现有 T01～T20 编号、依赖、P0/P1 工程边界。

| 阶段 | 对应任务 | 工业学习重点 | 复用 Java 经验 | 要能给出的解释或证据 |
| --- | --- | --- | --- | --- |
| 系统全景与设备身份 | T01 复盘 | 设备与业务系统职责；业务编码、HTTP 路径、Unit ID 的区别 | 外部系统接口与资源标识 | 在全景图中定位 Demo，并解释一个新的设备寻址场景；真实 Modbus 验证在 T04/T05 |

| --- | --- | --- |
| 已有经验，按需复习 | Maven、Spring、CRUD、Java 语法及通用数据库知识 | 不默认设基础考试；遇到影响项目判断的具体问题再解释。构建、测试和数据库约束验证仍由 Codex 完整执行 |

## 3. 每个任务的学习流程

每次会话先读取 [任务交接](06-tasks.md)，优先继续尚未通过的学习环节。工程已完成但学习未通过时，继续该任务复盘，不重复实现或直接进入下一任务。

1. **补足背景并明确问题**：Codex 先介绍业务场景和本轮必需的工业概念，用 Java 类比并说明类比的局限；不要求你凭空猜陌生术语。随后每次只提出一个未直接讲过的场景问题，等待你的回答，不公布该题完整答案。
2. **你提供设计**：先用自己的话说明方案和理由。保留首次回答，并注明是否得到提示；可说不确定或指出缺少的知识。
3. **讨论与补正**：Codex 检查职责、数据流和异常边界。遗漏时先给提示或反例，等你调整；陌生概念先用 Java 后端视角解释，再用新的场景确认理解。设计讨论通过后才开始编码。
4. **实现并讲解**：工程待完成时由 Codex 实现、执行工程检查，并结合实际文件解释入口、调用链、关键判断和失败处理；工程已完成则复用已有实现，不为复盘重写代码，不扩展到下一任务。
5. **预测与验证**：针对本任务的一个边界场景，你先预测结果；Codex 再运行对应检查，由你解释实际输出与预测的关系。提前给过结果的场景只算复习，另换场景验收。
6. **学习验收与面试练习**：Codex 提出一个未直接讲过的变式问题。你能解释关键设计、正确预测结果，且没有关键误区，才能将学习状态记为“通过”。面试材料中的已讲解案例属于复习，不能原题照搬后认定独立掌握。

### 3.1 通过条件与记录

- 工程状态仍使用 TODO、DOING、BLOCKED、DONE；学习状态使用“待评估 / 学习中 / 待补正 / 通过”，统一记录在 `docs/06-tasks.md`。
- 工程完成需要真实测试或验收证据。学习通过需要你的回答、对运行结果的解释及新场景判断；Codex 写出的代码和通过的测试不能代替学习证据。
- 工程相关问题沿用“预测后运行、再解释”的要求；纯领域拓展题采用新场景推理验收，明确记录“概念练习，无运行证据”，不能据此填写功能已实现。无需为概念题预先开发范围外模块。
- 亲手编码为可选练习，不是学习通过条件；你必须能解释关键代码、提出有理由的变更、预测并分析验证结果。工作年限也不自动等于本项目知识已掌握。
- 首次回答与辅助补正分别记录，不用讲解后的答案覆盖初答，也不把辅助完成写成独立掌握。未收到回答时保持待评估或当前学习状态，不能推定通过。
- 关键概念、数据流或结果判断错误时，停留在当前任务补正；不影响理解的术语和表达问题可列入复习项。每次只纠正具体误区，不机械重考整套问题。
- 进入下一任务前，当前任务工程须 DONE、学习须通过，并满足下一任务的工程依赖。环境导致验证受阻时可继续当前任务的概念讨论，工程仍记 BLOCKED，未运行的检查不能算通过。

### 3.2 会话入口

当前工程状态、学习状态及唯一待答问题以 [任务交接](06-tasks.md) 顶部为准，本页不重复维护即时进度。先补足全景背景，再继续当前任务尚未完成的领域理解；已经跳过的工具链题不重新设为门槛。

T01 的设备寻址复盘按“原题辅助补正 → 一个新场景判断”验收，保留原答及提示情况，不要求提前实现 T04/T05 的 Modbus 通信。T01 的工具链工程结果沿用已有证据，真实报文互通仍必须在 T04/T05 验证。概念补正通过不代表真实协议接入已完成。

T01 学习通过后才进入 T02。T02 从设备台账、当前快照、趋势、状态事件、告警为何各自存在开始，再讨论约束与异常输入；不重新讲整套 Java CRUD 或 SQL 入门课程。

## 4. 调整工期的规则

| 情况 | 调整方式 |
| --- | --- |
| 协议库超过 90 分钟仍不能连接 | 记录错误和尝试；查官方示例；必要时提出小范围更换方案，先同步决定 |
| 网络或依赖下载受限 | 标记 BLOCKED；可继续纯单元测试，不冒充集成已通过 |
| 页面开发超时 | 保留表格/基础状态显示；取消图表、美化、地图效果 |
| 第 5 天 P0 未通过 | 延长 MVP；优先修真实采集、状态、告警、测试，推迟 P1 |
| 已开始求职 | 与 Demo 并行推进，不把“Demo 完美”作为投递前提 |
| 精力不足 | 按实际可用时间减少当天任务，不以熬夜完成天数为目标 |
| 工程已完成，学习仍需补正 | 保留工程 DONE，继续当前任务的问答和验证；学习通过后再推进 |

允许简化页面形式、工具链和 P1 范围；不允许用 REST 假数据替代 Modbus，不允许移除告警去重或隐瞒测试缺失。

## 5. 里程碑验收

以下列出工程验收条件。工程里程碑与学习掌握情况分别报告；不能因代码验收通过而把对应学习状态一并标为通过。

- M0：T01～T02 完成，依赖版本和迁移记录可追溯。
- M1：T03～T07 完成，真实协议、状态和历史闭环通过。
- M2：T08～T13 完成，P0 验收全部通过，具备可复现演示。
- M3：T14～T20 按所选范围完成，增强项的验证状态明确。

“可以写到简历”不由开发天数决定，而由你能否运行、解释和证明已经做出的能力决定。个人项目应明确标注为模拟环境练习，不写成生产实施。
