# 10 Modbus 寄存器协议：唯一事实来源

协议名：AGV-DEMO-MODBUS；版本：1。以下业务映射由本项目自定义，不属于AGV行业通用标准。模拟器、客户端、测试、接口同时遵守本文件。

## 1. 通信约定

| 项目 | 约定 |
| --- | --- |
| 传输 | Modbus TCP，不是RTU over TCP |
| 默认服务端 | Compose内 `simulator:1502`；本地发布时 `127.0.0.1:1502` |
| 功能码 | 03 / 0x03：Read Holding Registers |
| 起始PDU地址 | 0 |
| 读取数量 | 8 个寄存器，业务数据16字节 |
| Unit ID | 1→AGV-001，2→AGV-002，3→AGV-003 |
| 更新周期 | 模拟器每秒原子更新8个寄存器 |
| 寄存器类型 | uint16；每个寄存器高字节在前 |
| 写入策略 | 监控后端不发送写指令；模拟器拒绝写功能 |

功能码03、16位寄存器及PDU寻址是协议规则，参考 [Modbus官方规范](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)。本Demo选用1502用于本地模拟，字段含义、单位和设备映射均为项目约定。

## 2. 映射表

| PDU偏移（代码传入） | 本文显示标签 | 字段 | 原始范围 | 解码 / 说明 |
| --- | --- | --- | --- | --- |
| 0 | 40001 | protocolVersion | 固定1 | 不等于1时INVALID |
| 1 | 40002 | runState | 0～3 | 0=IDLE，1=RUNNING，2=CHARGING，3=FAULT |
| 2 | 40003 | batteryPercent | 0～100 | 百分比整数 |
| 3 | 40004 | speedMmS | 0～3000 | mm/s；API `speedMps=raw/1000.0` |
| 4 | 40005 | positionCode | 0～9999 | 页面显示P0000～P9999，非真实坐标 |
| 5 | 40006 | targetCode | 0～9999 | 同上 |
| 6 | 40007 | faultCode | 0～65535 | 0无故障；非0有故障，未知码保留数值 |
| 7 | 40008 | heartbeat | 0～65535 | 每秒加1，到65535后回0 |

本文采用常见的40001显示标签表示holding register偏移0，实际请求传入0，不能传40001。真实设备手册可能有不同表示法，不能把“减40001”写成通用适配算法。参考 [库维护者的寻址说明](https://github.com/digitalpetri/modbus/blob/master/docs/user/concepts/addressing-unit-ids-and-data.md)。

所有业务量都占单个16位寄存器，本版没有float32、跨寄存器字序或字符串。不要擅自改为32位浮点再沿用此表。

## 3. 样本一致性与质量校验

- 校验正常响应的功能码、关联请求、寄存器数量和业务字段范围。
- faultCode=0 时 runState不能为FAULT；faultCode非0时必须为FAULT。
- IDLE、CHARGING、FAULT 时速度必须为0；RUNNING允许0～3000（可暂时停止）。
- 不符合上述约定则整个业务样本INVALID，保留最后有效业务值。
- 正常协议响应仍可证明通信存在；INVALID不能误作GOOD，也不能直接当OFFLINE。
- 不认识的非零faultCode仍可作为有效故障值保存，不应强制清零。
- heartbeat重复不算新业务样本；仅收到数据不代表底层设备仍在刷新。
- 模拟器在一次锁/不可变快照替换中同时更新整块值，客户端一次读取8个寄存器。

本规则只能约束自有模拟器。接入真实设备时要重新核对原子性、时间戳和一致性机制，不能凭本Demo保证设备的一致性。

## 4. 固定解码样例

原始寄存器数组：

```json
[1, 1, 76, 1200, 3, 7, 0, 65535]
```

对应16字节业务数据（不含MBAP及功能码头）：

```text
00 01 00 01 00 4C 04 B0 00 03 00 07 00 00 FF FF
```

必须得到：protocolVersion=1、RUNNING、电量76%、速度1.2m/s、位置3、目标7、无故障、heartbeat=65535。

下一轮heartbeat=0应认定为推进。Java需要按无符号16位解码，不能把65535解成-1；单位换算不能使用导致截断的整数除法。

测试至少使用这组独立给定的字节fixture，不允许只做“编码后再解码”而没有固定预期值。

## 5. 初始设备

| Unit ID | 编码 | 默认运行状态 | 电量 | 速度mm/s | 位置 | 目标 | 故障码 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | AGV-001 | RUNNING | 76 | 1200 | 3 | 7 | 0 |
| 2 | AGV-002 | CHARGING | 23 | 0 | 9001 | 9001 | 0 |
| 3 | AGV-003 | IDLE | 88 | 0 | 5 | 5 | 0 |

初始heartbeat=0。NORMAL下unit1位置在3～7循环，unit2/3位置不变；电量固定在表中值，不必模拟复杂耗电模型。用于验证NORMAL能恢复低电量时，选unit1；unit2初始23低于恢复阈值25，不能拿它证明低电量自动恢复。

## 6. 场景注入

| 模式 | 行为 | 心跳 / 响应 |
| --- | --- | --- |
| NORMAL | 恢复该unit的表格默认值与位置变化规则 | 心跳继续递增；正常响应 |
| LOW_BATTERY | 电量固定19，其余按该unit默认规则 | 心跳继续；正常响应 |
| FAULT | runState=FAULT、faultCode=2、speed=0 | 心跳继续；正常响应 |
| SILENT | 暂停所选unit的协议响应，管理接口仍可用 | 心跳可内部继续，客户端收不到 |
| FROZEN | 固定进入该模式时的全部8个寄存器 | 响应正常但heartbeat不变 |
| INVALID | 电量101；其余保持合法，作为故意坏样本 | 心跳继续；正常协议响应 |

每次模式切换都从该unit默认有效状态重建基础业务值，再应用模式覆盖；FROZEN例外，冻结切换前的有效快照（若此前INVALID则冻结最近有效快照）。进入SILENT只影响响应，不阻塞事件循环。

除 `/reset` 外切换模式不把heartbeat重置为0。`/reset` 将3台恢复初始业务值并从0开始；客户端将新的有效心跳差异视作新样本。本Demo不实现设备启动会话ID。

## 7. 异常响应

- 读区间越过0～7或数量非法：返回对应Modbus非法地址/非法值异常，客户端记录协议错误。
- 不支持的写功能：返回Illegal Function，不修改寄存器。
- 未登记Unit ID：不返回正常业务数据，模拟器按无响应处理，客户端在超时边界内结束。
- 不能以“找不到unit就返回全0”掩盖设备配置错误。

## 8. 协议变更规则

新增字段、修改单位或枚举会改变协议，先更新本文件和版本策略，再同步模拟器、解码器、API/DB映射与固定fixture。不要只改页面显示或某一端代码。
